# AI4KnowledgeNet · 蓝区→绿区移交清单

## 一、绿区已要求的交付物（对照）

| 绿区要求 | 蓝区交付 | 说明 |
|---------|---------|------|
| 整个项目代码 | ✅ `app/`（已打进离线包） | 不含 `reference/` 对照原型、不含密钥 `.env` |
| NebulaGraph 安装包 | ✅ `offline/nebula/` | 原生二进制，对应蓝区 `/usr/local/nebula`，**不含业务 data** |
| venv / site-packages | ✅ 等价交付：`offline/wheels/` | 离线 wheel，绿区按脚本安装到本机 Python（不必拷整棵 site-packages） |
| `.env` 配置 | ⚠️ 只交模板 `.env.example` | **真实 Key 不要随包传**；绿区按本机/内网 LLM 自填 |

离线包示例：`AI4KnowledgeNet-green-YYYYMMDD_HHMM.tar.gz`

---

## 二、绿区环境条件（请对方逐项确认）

### 必须具备

- [ ] **Windows**（建议 Windows Server / Win10/11，与蓝区同类即可）
- [ ] 已启用 **WSL1 + Ubuntu**（不是 WSL2 也行；蓝区当前为 WSL1）
- [ ] Ubuntu 内可用：`python3`、`pip`、`bash`、`tar`、`rsync`（或至少 `cp`）
- [ ] 本机可监听端口：**9669**（Nebula graphd）、**8000**（工作台 API）
- [ ] 有权把文件解压到本机磁盘（如桌面 / 项目盘）
- [ ] 安装路径可写：`/usr/local/nebula`（或同意改安装前缀）

### 强烈建议对齐蓝区版本（降低装不上概率）

| 项 | 蓝区当前参考值 |
|----|----------------|
| WSL 内核特征 | `*-Microsoft`（WSL1 常见） |
| Ubuntu | 蓝区为 **Ubuntu 26.04**（若绿区过旧，先对一下 `python3 -V`） |
| Python | **3.14.x**（包内 wheel 按此编译标签，如 `cp314`） |
| NebulaGraph | **3.8.0** 原生包 |
| 关键依赖 | fastapi / uvicorn / pydantic / nebula3-python 等（见 wheels） |

绿区请回传这几条命令结果，便于蓝区判断是否要重打 wheel：

```bash
uname -a
. /etc/os-release; echo "$NAME $VERSION_ID"
python3 -V
```

### 非必须（按业务需要）

- [ ] 绿区内网 **LLM / OpenAI 兼容接口**（没有也能手工入库，只是没有 AI 抽取）
- [ ] 同网浏览器访问（仅本机用则不需要放行防火墙）
- [ ] Cursor + MCP（可选；工作台浏览器即可入库）

### 明确不需要

- Docker / Hyper-V / 嵌套虚拟化  
- 把绿区材料回传到蓝区  
- 公网隧道（Pinggy / Cloudflare 等）

## 三、迁移成功后，蓝区还需要继续提供什么？

| 类别 | 内容 | 谁做 |
|------|------|------|
| 启动运维说明 | 启停 Nebula / API、健康检查、常见故障 | 蓝区已写在 `INSTALL_绿区.md`，可再口头交接 |
| Schema / 使用说明 | Tag/边含义、工作台操作、入库约定 | `docs/` + 演示 |
| 入库模板 | JSON / 材料字段约定（名称、来源路径、挂接技术点） | 蓝区提供样例；绿区按样例灌数 |
| `.env` 填值指导 | Nebula 连接默认本机；LLM 填**绿区内网**地址与 Key | 绿区自备 Key；蓝区只给字段说明 |
| Demo 数据（可选） | 线控底盘 demo 是否要灌到绿区空库 | 双方约定；默认**空库业务入库** |
| 版本更新 | 蓝区改代码后重新 `pack_green_zone.sh` 再传一包 | 蓝区 |
| 远程协助 | 绿区 Python/系统版本不一致时，蓝区按对方 `python3 -V` 重打 wheels | 蓝区 |

**一般不需要再从蓝区搬：** Nebula 业务库数据、绿区材料原文、生产密钥。

## 四、`.env` 字段清单（绿区自建）

```env
NEBULA_HOST=127.0.0.1
NEBULA_PORT=9669
NEBULA_USER=root
NEBULA_PASSWORD=
NEBULA_SPACE=auto_innovation_kg

# 以下仅当绿区有内网大模型时配置
LLM_API_KEY=
LLM_API_URL=
LLM_MODEL=
```

## 五、绿区安装验收（最短路径）

```powershell
wsl -d Ubuntu -u root -- bash <解压目录>/scripts/install_green_wsl.sh
```

验收：

1. `curl http://127.0.0.1:8000/health` → `status ok`  
2. 浏览器打开工作台，能「全貌」  
3. 新建一个测试技术点 / 材料成功  

---

## 六、若绿区坚持要「整棵 site-packages」

优先仍建议用 `offline/wheels` 安装（可重复、体积小）。  
若制度要求必须物理拷贝 site-packages，蓝区可再导出一份冻结目录，但需 **Python 小版本一致（同为 3.14.x）**，否则容易导入失败。
