# 技术情报雷达（Radar）说明

> 独立的"全网搜集 / 整理"模块，**不写图谱**。当前负责：多来源采集最新资讯与前沿资料，
> 去重整理后暂存独立库（`data/radar.db`），供浏览/导出/筛选。后续再决定如何与知识图谱集成。

## 访问
- 雷达界面：`http://<服务器IP>:8000/radar`
- 接口：`/radar/status` `/radar/sources` `/radar/items` `/radar/export` `/radar/probe` `/radar/run` 等
- 来源配置：`backend/radar_sources.json`（改动保存后点「探测」或重启即生效）

## 支持的来源类型（覆盖面）
| 类型 | 说明 | 可靠度 |
|------|------|--------|
| `arxiv_query` | arXiv 搜索 API（按关键词/分类 检索最新论文）| 高（实名开放、可直连）|
| `semanticscholar` | Semantic Scholar 论文搜索（标题/摘要）| 中（免费但限流，需重试）|
| `crossref` | Crossref 学术检索（标题/摘要）| 中（免费但限流）|
| `rss` | 通用 RSS/Atom（解析失败自动回退 HTML 链接提取）| 视源而定 |
| `sitemap` | 站点 sitemap.xml / robots.txt 定位 sitemap | 视源而定 |
| `page` | 列表页 HTML 链接提取（标题+URL）| 视源而定 |
| `urls` | 手工 URL 清单 | 高（自己给什么抓什么）|

## 用法
1. 打开 `/radar`，点「探测来源」看各源可达性（绿=可用、黄=拦截、红=失败）。
2. 点「立即采集」后台抓取（界面轮询进度）。
3. 结果按来源/关键词筛选，可「导出CSV/JSON」。
4. 需要更多源：编辑 `backend/radar_sources.json` 追加条目，复制现有对象改 url/query 即可。

## 收集不了的"高质量网站"怎么办（重要）

现实约束：公司网络走代理、多数网站反爬/JS渲染/付费墙，**不是所有好网站都能自动抓**。按问题给解法：

| 现象 | 可能原因 | 解决办法（按优先级） |
|------|----------|----------------------|
| **404** | 入口/列表页 URL 过期 | 换真实入口；去网站找"新闻/资讯"栏目 URL；用 `sitemap` 类型自动发现 |
| **403 / 反爬** | 站点拦截非浏览器请求 | ① 走该站**官方 RSS**（很多大站有，如 `https://site/feed`、`/rss`）② 用 RSSHub 等聚合服务生成该站订阅 ③ 找第三方**开放聚合API** ④ 公司代理白名单放行该域名 ⑤ 实在不行用「批量导入」人工喂 |
| **纯 JS 渲染（无内容）** | 页面内容靠前端 JS 加载 | ① 找它的 **sitemap.xml / 移动版(m.) / 文章直达URL** ② 抓它的**JSON API**（Network 里找 json 接口）③ 用渲染服务 |
| **429 限流** | 请求太频繁 | 调小 `max`，加大间隔；脚本已做每源限次，仍被限就换到非高峰 |
| **SSL/证书错** | 代理中间证书 | 引擎已 `verify=False`；仍失败看是否为域名被加签策略 |
| **付费墙/登录** | 内容要订阅 | 只能抓摘要/标题，正文需人工；此类质量最高但性价比最低，交给人工导入 |
| **内网地址** | 从外网不可达 | 需在公司内网机器上跑雷达，或把内网RSS/页面加进 `radar_sources.json` 后从内网采集 |

### 一句话原则
> 雷达强在"覆盖面+自动整理+导出"，被反爬的高质量站点用「RSS/API/白名单」来"曲线拿到数据"；
> 实在拿不到的（付费墙）设计上就是人工导入兜底，不牺牲系统稳定性。

## 蓝区 / 绿区跨网络同步（file sync bridge）

> 网络隔离时（外网不可达内网知识库），蓝区独立抓取整理，**随文件同步**到绿区后进候选库，
> 人工核对后一键入库。已落地，见 `scripts/blue_to_ingest.py`。

### 工作流
1. **蓝区**：抓取/整理出日报（`简报/tech_points.json`，含 技术点/领域/技术子类/供应商/客户/原文链接/入库建议），
   放到公司文件同步文件夹（如 `D:\download\底盘新技术检索_@_\2026-09-23\`）。
2. **绿区**：运行转换器写入候选队列（只写候选、不直接写图）：
   ```
   python scripts/blue_to_ingest.py                    # 自动找同步目录最新一期
   python scripts/blue_to_ingest.py <路径> --dry-run   # 先预览
   ```
3. **核对入库**：工作台 →「自动采集」，候选卡片显示 `子域 · 技术点 · 建议/供应商`，逐条「入库」（走
   `/collect/candidates/{id}/commit` = `commit_extraction`）或「删除」。

### 转换规则（关键）
- **蓝区不分类**：蓝区按「目标主题」检索（如 wet brake），只整理事实性字段；分类/归纳入库由绿区完成。
- **按 原文链接 + 子域 分组**：同一文章多子域（如 EMB/空气悬架/线控转向 同文）拆成多条候选；
  URL 加 `#sub=` 片段区分，`candidates.url` 唯一索引天然防重跑（重复同步自动跳过）。
- **子域由绿区映射**：`domain=底盘技术`；先按 技术点/子主题 复用图谱已有位置
  （EMB→`线控制动`、线控转向→`转向技术`、主动/空气悬架→`悬架技术`），再按 目标主题 映射
  （wet brake→`制动技术`），未命中则用主题原样作为子域。
- **技术点用通用形态**（蓝区 `技术点/子主题`，缺则主题兜底），供应商/客户/车型/备注 写入 `payload.notes` 供核对。
- `seen` 表记录干净 URL，避免未来自动采集重复入库。
- 蓝区 prompt 见 `docs/BLUE_ZONE_PROMPT.md`。
