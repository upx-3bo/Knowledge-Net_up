# 能力 enrichment 路线图

调研结论与建议优先级（结合当前工作台 / Nebula / Cursor MCP / 汽车技术点 DAG）。

## 关于「Nebula 三维」

- **不是** NebulaGraph 数据库内核自带 3D。
- 官方 **Nebula Explorer** 产品有 2D/3D 探索模式（偏运维/大图演示；3D 下编辑能力弱；部署偏重，本机无 Docker 时成本高）。
- **本工作台做法**：用 `3d-force-graph`（WebGL）在页面内做 **2D ↔ 3D 切换**，数据仍走现有 `/overview`、`/subgraph`——与业务详情/删除/Cursor 协助同一套交互。

## 已可做 / 近期高价值（P0–P1）

| 方向 | 说明 | 价值 |
|------|------|------|
| **2D/3D 切换** | 演示与大图浏览；操作仍以 2D+详情为主 | 观感与汇报 |
| **详情编辑 / 删边** | PATCH 属性、删单条 belongs_to/supports | 日常运维 |
| **材料录入 UI** | 类型、标题、链接、挂到技术点 | 闭环 L0 |
| **路径查询 UI** | 已有 `/path`，页面选两点看最短路径 | 技术关联解释 |
| **派生层级分数** | 子技术点数、材料数、入度 → rank / 展示层级 | 贴合多分支 DAG |
| **交叉边录入** | `relates_to` / 多父（驱制一体）表单 | 真实网络结构 |
| **Cursor/MCP 批量投喂** | 资料包 → 结构化草案 → 人工确认写入 | 内网 LLM 不可达时主路径 |
| **筛选图例** | 按 tag/边类型显隐、只看材料支撑 | 大图可读性 |

## 中期（P2）

| 方向 | 说明 |
|------|------|
| **材料溯源** | 共享盘/链接登记 + 页码/段落挂 `supports` |
| **证据面板** | 技术点详情列出支撑材料与摘要，一键打开来源 |
| **版本/变更日志** | 谁在何时加了点边（SQLite 旁路审计表即可） |
| **重复合并** | 同名技术点检测与合并 |
| **导出** | 子图/全貌导出 JSON、PNG、简报 Markdown |
| **权限角色** | 只读浏览 / 编辑 / 管理员（若多团队） |

## 远期（P3）

| 方向 | 说明 |
|------|------|
| **内网 LLM 直连** | VPN/DNS 通后一键抽取 |
| **情报采集** | 专利/资讯抓取（旧 demo intelligence） |
| **向量检索** | 材料切片 embedding，语义搜技术点 |
| **Nebula Explorer** | 有 Docker/Linux 后再挂官方大图工具（可选，不替代业务工作台） |
| **GraphRAG 问答** | 基于路径+材料的问答报告 |

## 不建议优先做的

- 为 3D 单独上 Explorer 全家桶（环境约束大、与业务表单割裂）
- 再引入第二套图引擎（SQLite 双写）
- 未有资料密度前就上复杂 GraphRAG

## 建议落地顺序

1. 工作台 2D/3D + 详情编辑/材料 UI（体验闭环）  
2. 派生层级 + 交叉关系（模型对齐你的业务描述）  
3. 资料批量进入 + 溯源字段（等你提供资料库）  
4. 内网 LLM / 向量检索（网络与算力就绪后）
