知识图谱工作台 · 工具原理与运行说明

说明本工具是什么、如何运转、由哪些代码支撑、谁能用什么，以及日后要做某类改进时该从哪里下手。

一、一句话总结

这是公司内部的一个网页版「汽车技术知识库」：把散在文件夹里的 PDF/PPT/Word/论文整理成一张"技术树"，每个节点是一个技术点或一份材料，节点之间的连线表达"属于哪个板块、支撑哪个技术点"；所有知识经过梳理后存在图数据库 NebulaGraph 里，大家通过浏览器查看、检索、增删改，AI 能协助抽取资料入库。

现在库里实际有：整车 1 个、领域 3 个（底盘技术 / 整车信息系统 / 汽车材料）、子域 22 个、模块 145 个、技术点 95 个、支撑文档 212 个，共 478 个节点、482 条关系。

二、整体怎么运转（三层结构）

浏览器 UI（前端网页）
      ↓  http 请求/JSON 数据
后端服务 FastAPI + Python（一台服务器上跑）
      ↓  nGQL 图查询
NebulaGraph 图数据库（本机/WSL 里跑）
  • 前端（页面）：负责"给人看、给人点"。画图、搜索框、统计数字、添加表单，全是浏览器里的代码（index.html / app.js）。它自己不存任何业务数据，一切都问后端要。
  • 后端（服务）：负责"听命令、算逻辑、读写数据"。浏览器每做一次操作，后端就执行对应的接口；同时承担 AI 抽取、历史记录、导入导出等逻辑。
  • 图数据库（数据仓库）：负责"存知识"。选它不用普通表格，是因为技术之间的关系是"一棵树 + 交叉引用"，图天生适合描述"谁属于谁、谁支撑谁"。

前端和后端是前后端分离的典型结构，但它俩部署在同一台服务器上、由同一个后端服务器托管页面文件——所以访问一个地址（比如 http://:8000）就能同时打开网页和调用接口，不用单独部署前端。

三、页面（UI）和后端是什么关系

页面上的东西背后调用的后端接口作用

关键点：

  • 读随便用：只要浏览器能到服务器，任何人可看、可搜、可导出。
  • 写要登录：增删改前需输入写入口令换取临时 token，防止误操作和无关人员乱改。
  • 每次写都会留痕：写在 SQLite 小数据库里，用来撤回、看最近记录、将来做审计。

四、NebulaGraph 在里面的角色

4.1 它是唯一的数据仓库

  • 整张知识图（节点+连线+属性）只存在 NebulaGraph 里（空间名 auto_innovation_kg）。
  • 它跑在本机 WSL1 里，不开 Docker——因为服务器是无嵌套虚拟化的虚拟机，只能这样装。
  • 后端启动时会与它建立连接池，所有查询/写入都走它。

4.2 有哪些后端代码在跟 Nebula 打交道

backend/nebula_client.py   连接管理（连上/断开/执行 nGQL）
backend/store.py           核心数据层：增删改查、搜索、子图、全貌、路径、统计（全部翻译成图查询）
backend/architecture.py    固定 6 层架构规则（哪些标签允许挂在哪些标签下）
scripts/nebula_health.py   健康检查（连不连得上、统计）
scripts/nebula_init.py / nebula_seed_retry.py / nebula_wait_and_init.py   建库建 Schema 初始化
scripts/backup_daily.py + snapshot.py   图数据快照备份
scripts/audit_architecture.py           全库合规审计
mcp_server/server.py       给 AI 助手用的读写工具（也是走 store.py → Nebula）

其中 store.py 是命脉：页面上 90% 的操作最终都是走到它，由它拼 nGQL 语句发给 NebulaGraph。改口径、提速、修 bug 大都发生在这里。

4.3 Nebula 为什么重要

  • 没有 Nebula → 后端起不来（连接失败），页面能打开但没有任何数据，任何操作都报"数据连接错误"。
  • 它的数据是唯一的：丢了就丢了（除非做过快照），所以有 backup_daily.py 定期快照。

链路：页面把用户意图变成请求 → 后端接口按架构规则拼成图查询 → Nebula 执行并返回 → 后端加工成页面要的 JSON → 前端画出来。store.py 是"翻译官"，architecture.py 是"规矩"，nebula.py 是"电话线"。

七、日后再做某类改进时，从哪里下手

下表按"想改进的方面"列出对应的文件 / 接口 / 操作，方便接到需求时快速定位。

想要优化页面 UI / 交互

1. 改前端文件：frontend/app.js（逻辑、作图）、frontend/index.html（结构、按钮）、frontend/styles.css（样式）。 2. 改完必须把 index.html 里的版本号升一档（app.js?v=…、styles.css?v=…），否则浏览器缓存旧文件看不到改动。 3. 前端改动无需重启后端，升版本号后浏览器刷新即可。 4. 若涉及新接口，先在 backend/routers/ 加路由并重启后端，再把前端接上。

想查看后端数据 / 数据库状态

  • 页面直接看：/stats（各层节点数）、/overview（整图）、/history（操作历史）、/activity/recent（最近记录）。
  • 命令行看一眼：python scripts/nebula_health.py（连接 + 统计）。
  • 深入审图：python scripts/audit_architecture.py --detail（列出结构问题明细）。
  • 直接连库查：进入 WSL1 用 nebula-console 连 127.0.0.1:9669，USE auto_innovation_kg; 后跑 nGQL。

想给知识库扩容（批量加数据）

1. 先导当前结构做参照：页面「导出知识架构」选根与终点层，导出 JSON。 2. 按模板补充新资料：页面「导入知识架构」→下载模板 → 填内容 → 校验 → 确认写入。 3. 大批量用脚本：写 scripts/ingest_*.py 读整理好的 JSON 建节点/边（参考 ingest_chassis_tech.py）。 4. 写入前建议先跑一次快照备份。

想调整知识结构（层级/关系规则）

  • 层级与父子约束集中在 backend/architecture.py：改 LEVELS、BELONGS_TO_PARENT、SUPPORTS_TARGETS、VID_PREFIX。
  • 改完重启后端，前端表单选项、导入导出校验会自动跟随（都读它）。
  • 改完跑 scripts/audit_architecture.py 复查全库是否合规。

想开启/调整 AI 能力

  • 编辑 .env：LLM_API_URL / LLM_API_KEY / LLM_MODEL（OpenAI 兼容接口，含华为内网模型网关）。
  • AI 业务代码在 backend/services/：extractor.py（抽取）、llm.py（模型调用）、fetch_url.py（网页抓正文）、import_review.py（复核）。
  • 可用状态在页面 AI 面板或 /ai/status 查看。
  • 改完 .env 需重启后端。

想提高页面/查询性能

  • 查询侧：backend/store.py 里的拼 nGQL 与取数逻辑（批量取数、overview 配额、子图深度）。
  • 前端侧：frontend/app.js 里的画布预算、渲染上限（软/硬阈值）、按层级/领域筛选减少一次性数据量。
  • 大改动前先备份，改动后对照 /stats、/overview 与页面加载耗时验证。

想做权限 / 审计 / 多角色

  • 现在只有一个写入口令（backend/auth.py，token 12h）+ 操作历史（backend/history.py）。
  • 要加角色分权：扩展 auth.py 的 token 携带角色，接口层按角色放行。
  • 要做审计面板：操作历史数据已齐（SQLite ops 表），加个查询页面即可。
  • 改后重启后端生效。

想改数据安全 / 备份策略

  • 快照脚本 scripts/backup_daily.py（每日、有变更才导出，同步共享盘可设 BACKUP_SHARE_DIR）。
  • 恢复：从 scripts/snapshots/ 的 snapshot_*.json 用导入链路/脚本回灌。
  • 建议把快照目录或复制件放到共享盘/异地。

八、当前系统状态速览

  • 运行方式：NebulaGraph 跑在本机 WSL1；后端 FastAPI 跑在 0.0.0.0:8000（标准端口；页面和文档由后端托管）。
  • 说明：曾遇到 8000 进程卡死无法访问的问题，期间在同机 8001 端口开过临时实例应急；恢复步骤见《演进与维护工作流》「重启后端」。
  • 数据量：6 层 478 节点 / 482 关系（整车 1、领域 3、子域 22、模块 145、技术点 95、文档 212）。
  • 三个领域：底盘技术、整车信息系统、汽车材料。
  • 写入保护：口令登录（12h token），每次写操作留痕（可撤回、可看最近记录）。
  • 备份：scripts/snapshots/ 有历史快照；backup_daily.py 支持每日检测+快照。
  • 访问文档：浏览器打开 http://<服务器IP>:8000/wiki/演进与维护工作流.html 及同类文档。

附：维护要点

改完页面记得升 app.js?v=/styles.css?v= 版本号；改完后端要重启 8000 进程；动数据前先跑一次快照。详细步骤见《演进与维护工作流》。
