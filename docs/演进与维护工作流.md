# 知识图谱工作台 · 演进历程 + 维护 & 更新工作流

> 此文档说明：① 我们是如何一步步做到现在的；② 后续如何维护、更新，包含具体操作和必要步骤。
> 适用对象：AI 助手 + 维护者。

## 第一部分：演进历程（我们怎么走到今天）

### 阶段 0：问题起点
- 底盘/汽车技术资料以散乱的文件（PDF/PPT/Word/论文）存放在共享文件夹，「靠文件名猜内容、靠经验联想关联」，无法沉淀、无法共享检索。

### 阶段 1：选型与地基
- 决定用**图数据库**（而非表格/文档）承载技术网络，因为技术是「多分支向下发散、可交叉汇合」的 **DAG** 结构，图的 `belongs_to / supports / relates_to` 天然匹配。
- 选定 **NebulaGraph**（分布式、可扩展、图查询语言 nGQL），Space 名 `auto_innovation_kg`。
- 环境：宿主机是 **OpenStack VM（无嵌套虚拟化）**→ 用 **WSL1 原生安装 Nebula**（不是 Docker/WSL2）。
- 建立 Schema：`domain / subdomain / technology / material` 四类节点，`belongs_to / supports / relates_to` 三类边。

### 阶段 2：搭建工作台
- 后端：**FastAPI + uvicorn**，分层架构 `routers → store.py → nebula_client.py → nebula3-python`。
- 前端：**vis-network(2D) + 3d-force-graph(3D, WebGL)**，静态文件由后端同源托管。
- 打通 Read 链路：列表、搜索、子图、全貌、路径。
- 打通 Write 链路：增删改节点/边，即时落库、幂等写入。
- 接入 **AI 协助**：自动抽取、协作提示词、确认写入、提炼/译中、复核。

### 阶段 3：性能与健壮性打磨
- **领域隔离**：`children()` 在父节点子树内做作用域查询，同名节点不跨领域误合并。
- **消除 N+1**：`_get_vertices_in` 批量取数；`find_path` 批量水合节点。
- **全貌/统计容错**：单 Tag 失败不整体崩溃；overview 修边、裁剪悬挂边。
- **前端**：层级筛选、领域筛选、2D/3D 切换、聚焦子图保留材料、材料全量加载（提 limit）、重定位版本号绕缓存。

### 阶段 4：底盘信息库「新架构」入库（最近）
- 提出 **11 大板块架构**：驱动/制动/转向/悬架/下车体设计/轮胎/传动系统/架构集成/电子电气集成/跨域特性/测试验证。
- 从真实 PDF/PPTX/Word 逐文件提取：主题、技术点、联系方、官网、电话、备注。
- 做成**可离线编辑的 HTML 目录**（浏览器 localStorage 保存编辑，预设+用户编辑合并）。
- 导出最终标签 → 用脚本按「底盘技术 → 板块 → 主题 → 技术点 → 材料」建成**独立新领域**（保留原有领域）。
- 期间修复了若干问题：材料全貌不显示（overview 预算+缓存版本号）、层级筛选被强制覆盖等。

## 第二部分：后续维护 & 更新工作流

### 每日/常规操作

#### 1. 启动服务（若 VM 重启后）
```powershell
# ① 启动 Nebula（WSL1）
wsl -d Ubuntu -u root -- bash /mnt/c/Users/<user>/Desktop/up_X/AI4KnowledgeNet/scripts/start_nebula_wsl1.sh
# ② 启动后端（旧 venv 有 uvicorn）
cd C:\Users\<user>\Desktop\up_X\AI4KnowledgeNet
Start-Process "<...>\ai-knowledge-base\venv\Scripts\python.exe" -ArgumentList "-m","uvicorn","backend.main:app","--host","0.0.0.0","--port","8000" -WorkingDirectory "C:\Users\<user>\Desktop\up_X\AI4KnowledgeNet" -WindowStyle Hidden
```
> 绑定 `0.0.0.0:8000`，同内网机器浏览器访问 `http://<服务器IP>:8000`。

#### 2. 健康检查
```powershell
# 后端
Invoke-RestMethod http://127.0.0.1:8000/stats
# 应返回 {"domain":..,"subdomain":..,"technology":..,"material":..}
```

### 3. 日常录入新资料（三种方式）
- **页面手工录入**：左侧「添加技术点 / 添加支撑材料」表单，填入后写入图谱。
- **页面 AI 录入**：粘贴资料 → 自动抽取 / 生成协作提示词 → 确认写入。
- **脚本批量导入**（大批量资料）：写一个 `ingest_*.py`，读取整理好的 JSON，按层级 + `belongs_to/supports` 建边。参考 `scripts/ingest_chassis_tech.py`。

### 4. 修改前端/后端后的更新流程（重要）
```powershell
# ① 改代码（前端 app.js / 后端 store.py 等）
# ② 改前端时【必须】更新 index.html 里的版本号，否则浏览器缓存旧代码看不到改动：
#    <script src="/static/app.js?v=旧号"></script>  →  改成新号（如 v=20260821a）
# ③ 只改后端（store.py 等 Python）需重启后端进程
# ④ 只改前端（app.js）无需重启后端，改版本号 + 刷新即可
```

### 5. 数据备份 & 快照
```powershell
# 导出当前统计快照
python scripts/nebula_health.py
# 关键数据源（底盘标签）放在 知识库-refs\_脚本\ 下，注意备份：
#   dir_tree_full.json / chassis_labels_exported.json / file_board_map.json / gen_new_edit.py / docx_extract.py
```

## 第三部分：维护的「必要检查清单」

每次改动后对照：

| 检查项 | 命令/操作 | 通过标准 |
|--------|----------|----------|
| 后端存活 | `/stats` | 返回 JSON，数值正常 |
| 前端加载 | 浏览器打开首页 + Ctrl+F5 | 界面正常，无控制台报错 |
| 节点/边一致性 | `/overview` | 各层数量与预期一致，无孤立材料 |
| 领域隔离 | 切换领域筛选 | 各领域互不串数据 |
| 材料显示 | 全貌切「材料」层 | 材料球体出现，不缺失 |
| AI 可用 | AI 面板状态 | 显示已配置或明确提示未配置 |

## 第四部分：多人协作（当前状态 + 后续要做的）

**当前**：数据共享同一图谱；无登录鉴权、无冲突提示、无审计。

**后续建议（按需落地）**：
1. **登录/鉴权**：加一层简单账号，区分「只读 / 编辑 / 管理员」。
2. **冲突提示**：编辑前读版本号，保存时若被他人改过则提示覆盖。
3. **审计日志**：用 SQLite 旁路记录「谁、何时、改了什么」（P2）。
4. **重复合并**：同名技术点/材料检测与合并。
5. **只读模式**：负责人之外的人默认只读视野。

## 第五部分：常用命令速查

| 用途 | 命令 |
|------|------|
| 前端改后强制刷新 | 浏览器 Ctrl+F5；改 `index.html` 的 `app.js?v=` 版本号 |
| 重启后端 | 结束旧 uvicorn 进程 → 重新 Start-Process（见上） |
| 启动 Nebula | `wsl -d Ubuntu -u root -- bash .../start_nebula_wsl1.sh` |
| 停止 Nebula | `wsl -d Ubuntu -u root -- bash /usr/local/nebula/scripts/nebula.service stop all` |
| 重置 Schema | `wsl -d Ubuntu -u root -- python3 .../nebula_wait_and_init.py` |
| 数据健康 | `python scripts/nebula_health.py` |
