知识图谱工作台 · 搭建说明 + 维护 & 更新工作流

此文档说明：① 这套系统是怎么搭建起来的（先做什么、再做什么）；② 后续如何维护、更新，包含具体操作和必要步骤。
适用对象：AI 助手 + 维护者。

第一部分：系统是怎么搭建起来的（搭建顺序）

按下面的顺序做，每一步都是下一步的前提，缺一步后面都跑不起来。

第 1 步：装好数据库 —— 先有"能存知识的地方"

  • 技术是「多分支向下发散、可交叉汇合」的 DAG 结构，选图数据库承载最合适；选定 NebulaGraph，空间名 auto_innovation_kg。
  • 宿主机是 OpenStack 虚拟机（不支持嵌套虚拟化），装不了 Docker/WSL2，所以 Nebula 用 WSL1 原生方式安装运行。
  • 完成标志：能用 nebula_health.py 或 python -c "import nebula3" 连上、能建 Space。

第 2 步：定好知识结构 —— 固定 6 层架构（全库唯一口径）

  • 全库固定 6 层：vehicle → domain → subdomain → module → technology → material。

- vehicle 是唯一根（无父）。 - 正常每层向下挂 1 层，belongs_to 严格单父树。 - material 不用 belongs_to，只通过 supports 挂到 module / technology（多对多）。 - 层不必填满（某子树最高只到 module 也合法，兼容旧数据）。 - relates_to 是平级交叉关联，不限层级。

  • 所有规则只写一份：backend/architecture.py。前端表单、导入导出、写库校验都读它，避免各模块口径不一致。
  • 完成标志：scripts/audit_architecture.py 全库审计 0 error。

第 3 步：搭后端 —— 让浏览器能读写数据库

  • 后端用 FastAPI + uvicorn（Python），分层：routers（接口） → store.py（图读写业务） → nebula_client.py（连接 Nebula）。
  • 提供接口：列表/搜索/详情/子图/全貌/最短路径（读），增删改节点与边（写），统计 /stats、健康 /health。
  • 完成标志：http://<IP>:8000/stats 返回各层节点数。

第 4 步：做前端 —— 让人能看、能点

  • 前端用 vis-network(2D) + 3d-force-graph(3D, WebGL)，静态文件由后端同源托管（访问 / 即打开页面）。
  • 图上有：全貌/子图切换、2D/3D、同心圆/力导向/树状布局、层级与领域筛选、节点详情、添加/编辑/删除、级联删除预告。
  • 完成标志：浏览器打开页面能看图、能点节点、增删改走通。

第 5 步：加数据管理 —— 登录留痕、导出导入、批量入库

  • 写入口令：增删改需口令换 token（12h 有效），浏览开放。
  • 操作历史：每次写操作记入 data/history.db（SQLite），支持撤回/重做，并作为「最近修改记录」数据源（最近 10 条：谁、何时、改了什么，新增节点可图内高亮）。
  • 选择导出 / 同构批量导入：/export/knowledge（任意根→某层级/节点，JSON/MD）、/import/template（自说明模板）、/import/knowledge（按 vid 更新、缺失新建、先校验后写）。

第 6 步：接入 AI（按需）—— 自动抽取、网页抓取、自动采集

  • AI 入库：粘贴资料 → 自动抽取 → 确认写入；复核、提炼/译中。
  • 网页抓取：输入 URL 抓正文，再走 AI 抽取。
  • 自动采集（可选）：从 arXiv/资讯/供应商专栏定期抓取 → 抽取 → 待人工确认入库（后台服务）。
  • 完成标志：AI 面板可用或明确提示未配置。

第 7 步：定运维 —— 备份与巡检

  • 每日快照：scripts/backup_daily.py（有变更才导出，写入 scripts/snapshots/）。
  • 常规巡检：nebula_health.py（连接/统计）、audit_architecture.py（结构合规）。
  • 一键重启：scripts/restart_backend.bat（停旧→等端口→起新→自检）。

这套顺序同时也说明「先做什么、后做什么」：数据库 → 结构 → 后端 → 前端 → 数据管理 →（可选）AI → 运维。每一层都建立在前一层的可运行验证之上。

第二部分：后续维护 & 更新工作流

每日/常规操作

1. 启动服务（若 VM 重启后）

# ① 启动 Nebula（WSL1）
wsl -d Ubuntu -u root -- bash /mnt/c/Users/<user>/Desktop/up_X/AI4KnowledgeNet/scripts/start_nebula_wsl1.sh

# ② 启动后端（新旧脚本二选一，推荐一键脚本）
# 一键（停旧→等端口→起新→自检）：
#   双击  scripts/restart_backend.bat
# 或手动：
cd C:\Users\<user>\Desktop\up_X\AI4KnowledgeNet
Start-Process "<...>\ai-knowledge-base\venv\Scripts\python.exe" -ArgumentList "-m","uvicorn","backend.main:app","--host","0.0.0.0","--port","8000" -WorkingDirectory "C:\Users\<user>\Desktop\up_X\AI4KnowledgeNet" -WindowStyle Hidden

绑定 0.0.0.0:8000，同内网机器浏览器访问 http://<服务器IP>:8000。
备注：本机自动化/其他会话可能看不到、杀不掉占用 8000 的进程；遇到旧进程卡死时，要在服务器桌面的任务管理器里结束占用 8000 的 python 进程后再启动（bat 脚本里也做了这件事）。

2. 健康检查

Invoke-RestMethod http://127.0.0.1:8000/health   # 期望 {"status":"ok"}
Invoke-RestMethod http://127.0.0.1:8000/stats    # 各层节点数

3. 日常录入新资料（四种方式）

  • 页面手工录入：左侧「添加技术点 / 添加支撑材料」表单（父层固定按 6 层架构约束）。
  • 页面 AI 录入：粘贴资料 → 自动抽取 → 确认写入；或 AI 复核（review-import）。
  • 批量 AI 入库：粘贴多份资料 JSON →「加载到入库预览」→ 确认写入。
  • 脚本/同构文件批量导入：导出 JSON → 修改/补全 → /import/knowledge 校验后入库（带 vid 走指主更新，缺失自动新建）。

4. 修改前端/后端后的更新流程（重要）

# ① 改代码（前端 app.js / 后端 store.py 等）
# ② 改前端时【必须】更新 index.html 里的版本号，否则浏览器缓存旧代码看不到改动：
#    <script src="/static/app.js?v=旧号"></script>  →  改成新号（如 v=20261014b）
#    <link rel="stylesheet" href="/static/styles.css?v=…" > 同理
# ③ 只改后端（store.py 等 Python）需重启后端进程
# ④ 只改前端（app.js）无需重启后端，改版本号 + 刷新即可

5. 数据备份 & 快照

# 变更检测 + 快照（写入 scripts/snapshots/）
python scripts/backup_daily.py            # 每日；有变更才导出
python scripts/backup_daily.py --force    # 强制导出
python scripts/backup_daily.py --check    # 只检测不导出
# 架构合规巡检
python scripts/audit_architecture.py       # 0=通过 / 2=有 error
python scripts/nebula_health.py            # 连接 + stats
# 关键数据源（底盘标签）在 知识库-refs\_脚本\ 下，注意备份

第四部分：多人协作（当前状态 + 后续要做的）

当前：

  • 读写分离：浏览开放（任何人内网可看、可查、可导出）；写入需口令登录（token 12h）。
  • 每次写操作记入操作历史（SQLite），支持撤回/重做、最近修改记录展示「谁何时改了什么」。
  • 无冲突提示、无细粒度角色权限。

后续建议（按需落地）： 1. 角色权限：区分「只读 / 编辑 / 管理员」，口令分发给不同组。 2. 冲突提示：编辑前读版本号，保存时若被他人改过则提示覆盖。 3. 审计面板：把操作历史升级为可筛选的完整审计日志（按人/按时间/按动作）。 4. 重复合并：同名技术点/材料检测与合并。 5. 订阅/消息：写操作实时通知（当前是刷新面板看最近记录）。
