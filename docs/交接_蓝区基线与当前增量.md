## 二、核心技术底座演进

### 1. 数据引擎：SQLite demo → NebulaGraph 主引擎
- **做了什么**：弃用 SQLite 双引擎，统一走 NebulaGraph（`auto_innovation_kg` Space，WSL1 原生安装）。
- **如何实现**：`backend/store.py` 全部用 **nGQL** 操作；`backend/nebula_client.py` 封装连接池（ConnectionPool，max 8）+ 会话 + 错误包装。
- 图模型：`domain / subdomain / technology / material` 四 Tag，`belongs_to / supports / relates_to` 三类边。

### 2. 运行环境
- OpenStack VM（无嵌套虚拟化）→ **WSL1 原生 Nebula**（非 Docker/WSL2）。
- 后端 FastAPI + uvicorn（`0.0.0.0:8000`），前端静态同源托管。
- 驱动 `nebula3-python==3.8.3`（Thrift 协议）。

## 三、能力增量清单 + 实现方式

### A. 检索与可视化

| 增量 | 如何实现 |
|------|---------|
| **2D/3D 双视图** | vis-network(2D) + 3d-force-graph(WebGL)；`drawGraph2d/drawGraph3d` |
| **同心圆/力导向布局** | <code>computeRadialPositions</code> 扇区分组 + 力导向重排（`btnLayoutForce`）|
| **3D 标注分级** | `label3dTags` 按层级开关标签（`label3dControls`）|
| **层级筛选 + 含上层/仅本层** | `layerCap/layerScope`，`filterByLayer` 按 `LAYER_RANK` 过滤 |
| **领域筛选（子库隔离）** | `domainFilter`，`filterByDomain` 按 belongs_to 祖先归域；`children()` 作用域隔离保证**同名不跨域误并** |
| **搜索 + 高亮命中** | `searchNodes` + `highlightSearch`，`focusIn2D` 自动切 2D 高亮 |
| **聚焦子图保留材料** | `filterByLayer` 子图模式保留与 focus 直连的 supports 材料 |
| **查最短路径** | `find_path` → `FIND SHORTEST PATH ... BIDIRECT`，批量水合节点 |

### B. 图谱编辑（CRUD）

| 增量 | 如何实现 |
|------|---------|
| **添加技术点（多级）** | `addForm` + `parent_name/mid_name`；`submitAdd` 调 `/vertices` |
| **添加材料表单** | `matForm`：类型/标题/摘要/来源链接，`submitMaterial` 建节点+supports 边 |
| **编辑/删除节点边** | `PATCH /vertices`、`DELETE /vertices/{vid}`（WITH EDGE 级联）、`DELETE /edges`（先查存在再删）|
| **属性白名单 + vid 消毒** | store 层 `TAG_PROPS/EDGE_PROPS` + `_sanitize_vid`，防脏数据 |
| **幂等写入** | `INSERT ... IF NOT EXISTS` + 确定性 vid，重复导入不产生重复节点 |

### C. AI 协助入库（核心增量）

| 增量 | 如何实现 |
|------|---------|
| **网页抓取 + 提炼入库** | `backend/services/fetch_url.py`：httpx+代理（读 Windows 系统代理）+ lxml 提取正文；`/ai/fetch` → 填入文本框 → `/ai/extract` → 可编辑表单 → `/ai/commit` |
| **可编辑抽取结果表单** | `renderAICards`：领域/子领域/技术点/文档/支撑勾选/备注全部可编辑 + 增删 |
| **同名并入标注** | `/ai/match` → `match_extraction`：按名称在目标领域作用域查，标注「已存在·复用」/「将新建」 |
| **同名才并入** | `commit_extraction` 的 `_ensure`：按名称查，找到复用已有节点、否则新建；文档支撑边按名称建 |
| **AI 提炼 / 译中** | `/ai/assist`：`refine/translate` 模式，回填描述与关键词 |
| **LLM 超时容错** | `llm.py`：chat_json 默认超时 **300s**、chat_text 180s（修复大文本抽取超时）|
| **规则/AI 复核** | `import_review.py`：`rule_check` + `ai_review_extraction` 二轮 QA |

### D. 多人协作与部署（最新增量）

| 增量 | 如何实现 |
|------|---------|
| **单写入口令鉴权** | `backend/auth.py`：无状态 HMAC token（`issue_token/verify_token`）；写接口加 `Depends(require_write_token)`；`/ai/login` 发 token |
| **前端登录** | `btnLogin` + `loginMask` 弹窗；`api()` 401 自动弹登录；token 存 sessionStorage；已登录显示「✓ 已登录」 |
| **只读/可写区分** | 浏览(GET)免登录；写(POST/PATCH/DELETE、AI commit/direct-write)需口令 |
| **口令放 .env** | `WRITE_PASSWORD`（默认 dipan123，**务必改掉**）|
| **开机自启** | `scripts/start_service.bat` + 启动文件夹 `.lnk`（登录自启，无需管理员）：先启 WSL Nebula → 延时 → 启后端（端口占用则跳过）|
| **图形前端缓存修复** | `index.html` 维护 `app.js?v=` 版本号，改前端后必须更新版本号强制拉新 |

## 六、给接手者的注意事项

1. **口令安全**：`.env` 的 `WRITE_PASSWORD` 是团队写入口令，默认 `dipan123`，**务必立即修改**，改后重启后端。
2. **前端版本号**：改 `app.js` 后必须更新 `index.html` 的 `?v=`，否则团队浏览器看旧版。
3. **数据共享**：所有人连同一份 Nebula；无冲突提示、无审计（后补项）。
4. **重启服务**：VM 重启后登录 Windows 会自动拉起（start_service.bat）；手动也可运行该 bat。
5. **领域隔离**：多人各管各领域，`children()` 作用域保证同名不跨域误并。
